Where: End result (lines 22, 28, 34–35)
Finding: The document treats ZDT version checks as a single comparison against "stored versions" / "stored index metadata" ("either matches expected versions with all required version aliases present or represents a valid rollback where the application is older than stored versions" and Scenario 2: "whose expected model versions are older than or equal to stored index metadata (with at least one older type and no newer type)... treats the run as a valid rollback noop without modifying aliases and exits 0"). In reality, ZDT checks two separate version maps in sequence: `mappingVersions` in `src/core/packages/saved-objects/migration-server-internal/src/zdt/model/stages/init.ts:142-186` and `docVersions` in `src/core/packages/saved-objects/migration-server-internal/src/zdt/model/stages/documents_update_init.ts:59-98`. Because `ui` and `background_tasks` pods run with `skipDocumentMigration: true` (`src/core/packages/saved-objects/migration-server-internal/src/zdt/state/create_initial_state.ts:19-28`, `src/core/packages/saved-objects/base-server-internal/src/saved_objects_config.ts:60`), serving pods routinely advance `mappingVersions` and create version aliases while `docVersions` still lags behind for `kb-migrator-kb` to convert. In addition, even when `mappingVersions` is `lesser` (rollback), if `docVersions` is `greater` (interrupted earlier upgrade) ZDT still transitions to `SET_DOC_MIGRATION_STARTED` (`init.ts:181` -> `documents_update_init.ts:74`), and if `mappingVersions` is `equal` while a version alias is missing, ZDT still runs `UPDATE_ALIASES` (`init.ts:174`) regardless of `docVersions`.
Suggestion: Explicitly require checking both mapping versions and document versions independently, and narrow rollback noop to require no newer application version in either map plus alias presence whenever mapping versions are equal.
