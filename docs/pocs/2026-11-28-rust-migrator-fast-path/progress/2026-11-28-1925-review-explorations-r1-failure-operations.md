### How each direction fails in production and who finds out

- **`rust-migrator-wrapper`**
  - **Silent skip on manifest/config drift:** If the build-time manifest omits an active SO type (or diverges from Kibana's tier/override precedence), ZDT version checks filter stored `_meta` by `knownTypes`, report `equal`, and exit `0`. `kibana-controller` marks `Migration=True` and completes rollout; **customers or solution teams find out later** when `ui`/`background_tasks` read unmigrated documents or hit mapping errors.
  - **Loud Job failures / hangs on ES cold start, partial failures, or OTLP flush:** Without Kibana's startup retry loop (401/403/429/503/ES-initializing waits of 8–21s+) and a bounded OTLP flush timeout, transient ES warmup or collector stalls either burn all 6 Kubernetes Job retries (`BackoffLimit` defaults to 6, `Migration=False`) or hang indefinitely (zero probes, `ActiveDeadlineSeconds: nil`). **Serverless on-call finds out** via stuck rollout completion or `kibana_controller_status_migration=2` alerts.
  - **Rollback CPU spike or masked conflicts:** Falling back to Node.js on `lesser` versions spikes fleet CPU during emergency rollbacks; loosening the check masks `FATAL` version conflicts. If pod memory/CPU limits are lowered in the proposed follow-up, every fallback run OOMKills (exit 137) without heap snapshots if `archive-csi-volume` is removed — **on-call finds out** during the first stateful release wave.
  - **Non-Serverless Docker breakage:** Branching in the shared `bin/kibana-docker` script without guarding image flavor/binary presence breaks ECH/ECK/self-managed/IronBank images configured with `NODE_ROLES=["migrator"]` — **release/customer support finds out** via immediate exit 127 or keystore/v2 failures.

- **`controller-manifest-gate`**
  - **Permanently stranded failed migrations:** Keying `expectedMigrationHash` only on `(migrationFingerprint, pluginEnablementConfigHash)` means a failed Job (`Migration=False`, `Migrated=True`) will no longer self-heal on cert rotation, `NODE_OPTIONS`/memory overrides, or stateless hotfixes to migrator/transform code. Projects remain failed with `ReconciliationCompleted` already fired until **on-call notices `kibana_controller_status_migration=2`** and manually forces re-trigger per project.
  - **Silent skip on missed config inputs or restored clusters:** If `pluginEnablementConfigHash` misses `pricing.tiers.products`, `projectOverrides.kibanaEnv`, or a new conditional flag, or if the creation Job is skipped on a restored/re-hydrated ES cluster whose `ui`/`background_tasks` pods skipped document migration, no migrator pod ever runs and `kibana_controller_status_migration` stays `3: Succeeded`. **Customers find out** from broken saved objects, and on-call has zero migrator pod logs to inspect.
  - **Cutover/rollback storm and registry outage blast radius:** Changing the hash formula invalidates `Status.ObservedMigration` across all ~16,500 projects simultaneously when `kibana-controller` upgrades or rolls back, causing a fleet-wide Job storm; if OCI labels are read from a registry at reconcile time, a registry outage or rate-limit stalls reconciliation across the fleet — **control-plane on-call finds out**.

- **`lightweight-node-fast-path`**
  - Shares the **silent manifest-omission skip**, **in-container fallback OOMKill/throttling trap** if pod limits are lowered, and **shared `bin/kibana-docker` non-Serverless exposure** with `rust-migrator-wrapper`.
  - **Observability blind spot:** As written, it skips Core boot without wiring ECS JSON logging (`service.node.roles`, `service.id`), `initMetrics` OTel shutdown flush, or fallback-reason logging; **on-call finds out** during incidents when `kibana.saved_objects.migrations.time` drops or fallback pods fail with disjoint logs.

- **`status-quo-plus-v3`**
  - **Fleet-wide rotation/rollout burst contention:** `kb-migrator-kb` requests `125m` CPU with a `1` CPU limit (8x burst) and is excluded from startup CPU boost. Cluster-wide triggers (`uiam-shared-secrets` rotation via `enqueueAllKibanaAppConfigs`, CA bundle updates, `kibana-base-yaml` changes, stateless releases) spawn thousands of 998m-burning Node.js pods for 29–48s, throttling co-located `ui`/`background_tasks` pods and delaying `RolloutReporting.ReconciliationCompleted`. **Serverless/infrastructure on-call finds out** via node CPU throttling, rollout latency, or co-located pod SLO burn.
