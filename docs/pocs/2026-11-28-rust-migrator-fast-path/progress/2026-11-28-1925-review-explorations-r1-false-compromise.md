Finding: `lightweight-node-fast-path` assumes avoiding the 164-188 plugin `setup()` boot in Node.js requires bypassing `PluginsService` entirely with a build-time static manifest and a separate two-process fallback entrypoint ("skipping `plugins.discover()` and `plugins.setup()` across all 164–188 plugins", "Same build-time manifest accuracy and transitive-plugin-enablement resolution complexity as `rust-migrator-wrapper` (must track `allowlistPluginGroups`, `<plugin>.enabled`, and the 5 conditional flags)", "On any pending document migration, V2 takeover, or unknown plugin override, spawns/falls back to full `bin/kibana`"). Suggestion: Compare a split `migrations` plugin entrypoint against the static build-time manifest + two-process fallback design, especially given that the split entrypoint also accelerates stateful rollout waves.
